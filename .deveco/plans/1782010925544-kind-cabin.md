# ArTree 自由布展系统 — 完整技术方案

## Goal

实现用户能够：
1. **选择/导入场景模型**（预设展厅 + 用户自行导入的 .glb 场景）
2. **导入作品模型**（用户自己的 .glb/.gltf 3D 作品）
3. **在场景中自由摆放/设计**这些作品（拖拽、旋转、缩放、选中、删除）
4. **3DGS 场景**作为增强场景类型可选接入

## Scope / Non-goals

**包含**：
- 预设展厅场景列表选择
- 用户导入 .glb 场景模型
- 用户导入 .glb/.gltf 作品模型
- 原生 3D 环境中的 raycast 选中 + 位置/旋转/缩放调整
- 3DGS（Spatial Recon Kit）场景模型加载与渲染
- 布展方案序列化保存/加载
- 用户展厅页面（从主菜单进入）

**不包含**：
- 多人在线协同（Phase 4 远期规划）
- 虚拟门票/IAP 商业闭环
- AI 自动策展布局
- 3DGS 场景的采集/重建（仅加载已生成的 .ply/.mp4 模型）

## Current State And Constraints

### 现有架构
- **4 条渲染路径**：ArkGraphics3D 原生（David/Chinese/Gallery）、WebView+Three.js、ThreeJsHost+onInterceptRequest、Python 离线管线
- **已有布展系统**：WebView 路径（`rawfile/web/index.html`）有完整的画作选择、ghost 预览、slot 吸附、raycast 选中、fine-tune 面板、导出/导入 JSON
- **已有 Slot 系统**：`WhiteCubeSlots.ets`、`SalonCarreSlots.ets`、`ChineseGallerySlots.ets` 定义了预设展厅的挂画位
- **SpatialReconPilot**：仅占位页，无 SDK 调用
- **3DGS 长期计划**：`docs/3DGS_LONG_TERM_PLAN.md` 已有 5 阶段路线

### 关键 API 发现（改变方案的核心）

**1. `Scene.load(uri?: ResourceStr)` — 接受字符串路径！**
- `ResourceStr = string | Resource`
- 可以传入沙箱文件路径如 `"/data/app/.../files/user_models/scene.glb"`
- 无参调用返回空场景

**2. `Scene.importScene(name, scene, parent)` / `Scene.importNode(name, node, parent)`**（since 18）
- 可以将一个 Scene 的内容合并到另一个 Scene 中
- 这是加载用户作品模型并放入当前展厅场景的关键 API

**3. `Node.children.append/remove` — 完整的节点树操作**
- 动态添加/删除子节点
- `Node.position/rotation/scale` 可读写

**4. `Camera.raycast(viewPosition, params)` — 原生射线检测**（since 20）
- 返回 `RaycastResult[]`（node, centerDistance, hitPosition）
- 支持限定搜索范围（rootNode 参数）

**5. `RenderResourceFactory.createMesh + createGeometry` — 运行时创建几何体**
- `CustomGeometry`：自定义顶点/索引/法线/UV
- 预制几何：CubeGeometry, PlaneGeometry, SphereGeometry, CylinderGeometry

**6. `RenderContext.registerResourcePath(protocol, uri)` — 自定义协议映射**（since 20）
- 可注册 `sandbox://` 协议映射到沙箱目录
- 之后 Scene.load 可使用 `"sandbox://user_models/model.glb"`

**7. `GSPlugin.loadGSNode(scene, params, parent?)` — 3DGS 模型加载**（since 6.0.1/21）
- 加载 .ply/.mp4 3DGS 模型为场景节点
- 返回 `GSNode extends Node`，支持 position/rotation/scale
- 需要 `Scene.loadPlugin(GSPlugin.PLUGIN_ID)` 预加载插件
- 4 种特效：Retro, Comic, ObraDinn, ColorEditing

**8. `SceneResourceFactory.createNode(params)` — 创建空节点**（since 12）
- 可作为分组/锚点使用

### 约束
- **SDK 版本要求**：
  - `Scene.load(string)` / `importScene` / `importNode`：API 12+ ✅（项目已用 API 20）
  - `Camera.raycast`：API 20+ ✅
  - `RenderContext.registerResourcePath`：API 20+ ✅
  - `createMesh` + `CustomGeometry`：API 18+ ✅
  - `GSPlugin.loadGSNode`：API 21+（6.0.1）⚠️ **需确认当前构建目标是否需要升级**
  - `cloneNode`：API 23+ ⚠️ 可选功能
- **3DGS 格式**：支持 PLY（标准 3DGS 点云）和 MP4（压缩格式）
- **用户导入格式**：.glb 优先（自包含单文件），.gltf 需多文件处理
- **HarmonyOS 文件选择器**：`DocumentViewPicker` 无文件类型过滤，需后验证扩展名
- **权限**：Picker 方式无需额外权限；若需持久访问需 `ohos.permission.FILE_ACCESS_PERSIST`

### 核心流程

#### 流程 A：选择/导入场景模型

```
用户点击"选择展厅"
  → 展示预设场景列表 (white_cube, salon_carre, chinese_gallery, david)
    + "导入自定义场景" 按钮
  → [预设] Scene.load($rawfile('gltf/xxx/scene.gltf'))
  → [导入] DocumentViewPicker.select() → 拷贝到沙箱
         → Scene.load(sandboxPath) 或 registerResourcePath 后 Scene.load("sandbox://...")
  → 创建 Camera + Lights
  → 进入编辑模式
```

#### 流程 B：导入作品模型并摆放

```
用户点击"添加作品"
  → DocumentViewPicker.select() → 验证 .glb/.gltf
  → 拷贝到 context.filesDir/user_artworks/
  → Scene.load(artworkPath) 加载作品为独立 Scene
  → scene.importScene(name, artworkScene, scene.root) 合并到当前场景
  → 设置初始 position (相机前方 2m)
  → 进入放置模式 (ghost 跟随 + 确认放置)
```

#### 流程 C：交互式摆放

```
[选中模式] 单击 → Camera.raycast(screenPos, {rootNode}) → 获取 hitResult.node
  → 高亮选中节点 (修改 material 或 添加 outline effect)
  → 显示属性面板 (位置/旋转/缩放滑块)

[拖拽移动] 选中后拖拽 → 每帧 raycast 到地面/墙面
  → 更新 node.position 到 hitPosition

[旋转/缩放] 属性面板滑块 → 更新 node.rotation / node.scale

[删除] 选中后点击删除 → node.parent.children.remove(node)
```

#### 流程 D：3DGS 场景

```
[加载 3DGS 场景] 用户选择 .ply/.mp4 3DGS 模型
  → Scene.loadPlugin(GSPlugin.PLUGIN_ID)
  → GSPlugin.loadGSNode(scene, {uri: modelPath}, scene.root)
  → 返回 GSNode，支持 position/rotation/scale 操作
  → 可应用特效：Retro/Comic/ObraDinn/ColorEditing
```

### 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 场景加载方式 | `Scene.load(string)` 原生 | API 支持字符串路径，无需 WebView 回退 |
| 作品合并方式 | `importScene()` | 官方 API，保证节点树正确合并 |
| 3D 交互方式 | `Camera.raycast()` | 原生射线检测，无需 WebView |
| 文件选择 | `DocumentViewPicker` | 无权限需求，用户主动选择 |
| 用户模型格式 | 仅 .glb | 自包含单文件，无外部引用问题 |
| 资源路径映射 | `registerResourcePath("sandbox", filesDir)` | 统一资源引用，支持 glTF 内部相对路径解析 |
| 3DGS 接入 | `GSPlugin.loadGSNode()` | 官方 SDK，与 Scene 系统无缝集成 |
| 状态管理 | `@State` + 自定义 Editor 类 | 编辑器状态复杂，需封装专用管理类 |
| 布展序列化 | JSON 文件存入 preferences | 轻量，无需数据库 |

### 数据模型

```typescript
// 布展方案
interface ExhibitionLayout {
  id: string;                    // 唯一 ID
  name: string;                  // 展厅名称
  sceneUri: string;              // 场景模型路径（rawfile 或 沙箱）
  sceneType: 'gltf' | '3dgs';   // 场景类型
  placedArtworks: PlacedArtwork[];  // 已放置的作品列表
  cameraPosition: Position3;     // 保存的相机位置
  cameraRotation: Quaternion;    // 保存的相机旋转
  createdAt: number;             // 创建时间戳
  updatedAt: number;             // 更新时间戳
}

// 已放置的作品
interface PlacedArtwork {
  id: string;                    // 放置实例 ID
  modelUri: string;              // 模型文件路径
  modelName: string;             // 显示名称
  position: Position3;           // 世界坐标位置
  rotation: Quaternion;          // 旋转
  scale: Scale3;                 // 缩放
  nodePath: string;              // 场景节点路径（用于 getNodeByPath 恢复引用）
  slotId: string;                // 吸附的槽位 ID（可选）
}
```

## Execution Sequence

### Phase 0: 基础设施 — 沙箱文件管理 + 资源路径注册

1. **创建 `ModelManager.ets`**
   - `pickModelFile(context: Context): Promise<string>` — 调用 DocumentViewPicker，验证 .glb 扩展名，返回沙箱路径
   - `copyToSandbox(context: Context, srcUri: string, subDir: string): Promise<string>` — 将选择器返回的 URI 拷贝到 `context.filesDir/subDir/`
   - `registerSandboxProtocol(renderContext: RenderContext, context: Context): void` — 调用 `renderContext.registerResourcePath("sandbox", context.filesDir)`
   - `listUserModels(context: Context, subDir: string): string[]` — 列出沙箱中已导入的模型
   - `deleteModel(context: Context, path: string): void` — 删除沙箱模型文件

2. **验证 `Scene.load(stringPath)` 可用性**
   - 将 DamagedHelmet.glb 拷贝到沙箱
   - 尝试 `Scene.load(sandboxPath)` 加载
   - 记录是否成功、是否需要 `registerResourcePath`

### Phase 1: 场景模型加载 — 预设+用户导入

3. **创建 `SceneSelector.ets` 组件**
   - 预设场景列表（白立方、沙龙、中国馆、大卫馆缩略图+名称）
   - "导入自定义场景" 按钮（调用 ModelManager.pickModelFile）
   - 返回选择的场景 URI

4. **创建 `UserGalleryPage.ets` 基础框架**
   - 场景选择 → Scene.load() → Component3D 渲染

   - FirstPersonCameraController 接入（摇杆+拖拽视角）

### Phase 2: 作品模型加载与节点管理

5. **创建 `GalleryEditor.ets`**
   - `loadScene(uri: string): Promise<void>` — 加载展厅场景

### Phase 3: 交互式摆放 — Raycast + 拖拽

7. **实现 raycast 选中**
   - Component3D 的 TapGesture → 获取点击坐标
   - 转换为 NDC 坐标 → `Camera.raycast(ndcPos, {rootNode: artworksRoot})`
   - 命中节点 → GalleryEditor.selectArtwork
   - 未命中 → GalleryEditor.deselectArtwork

8. **实现 ghost 预览 + 放置确认**
   - 导入作品后先创建半透明 ghost 节点（scale 略小 + 半透明 material）
   - 每帧 raycast 到地面/墙面 → ghost.position 跟随 hitPosition
   - "确认放置" 按钮 → 移除 ghost，显示正式节点

9. **创建 `PropertyPanel.ets`**
   - 位置 X/Y/Z 滑块
   - 旋转 Y 滑块（绕 Y 轴旋转，最常用）
   - 缩放 统一滑块
   - 删除按钮
   - 精细调整按钮（±1cm / ±5° / ±10%）

10. **实现拖拽移动**
    - 选中节点后，长按+拖拽 → 每帧 raycast 到地面
    - 更新 node.position = hitPosition（保持 Y 高度不变或贴合地面）

### Phase 4: 3DGS 场景接入 (Spatial Recon Kit)

### Phase 5: 布展保存/导出 + 用户展厅页面

15. **完善 `UserGalleryPage.ets`**
    - 布展方案保存/加载/导出/导入按钮
    - 已保存展厅列表
    - 预览模式（隐藏编辑 UI，纯漫游）
    - 与现有主菜单 Index.ets 集成

## Risks And Compatibility

| 风险 | 影响 | 缓解 |
|------|------|------|
| `Scene.load(stringPath)` 在某些设备/版本上不支持沙箱路径 | 用户导入模型无法原生加载 | 回退到 `registerResourcePath` 方案；最终回退到 WebView+Three.js |
| 3DGS 需要 API 21+，当前项目 targetSdkVersion 为 API 20 | GSPlugin 不可用 | Phase 4 独立，不影响 Phase 0-3；评估升级风险后决定 |
| `importScene` 可能丢失某些 glTF 扩展（如KHR_materials_unlit） | 导入的作品渲染效果不一致 | 测试多种 glTF 文件，记录兼容性矩阵 |
| 大型 .glb 文件（>100MB）加载时间过长 | 用户体验差 | 显示加载进度条，异步加载，考虑 LOD |
| `DocumentViewPicker` 无文件类型过滤 | 用户可能选择非模型文件 | 拾取后立即验证扩展名，提示重新选择 |
| 3DGS 设备兼容性（低端设备可能不支持） | 3DGS 功能不可用 | `HMS_SpatialRecon_IsSupport` 前置检查，不支持时隐藏选项 |
| ArkTS 严格模式禁止 `as` 断言 | 某些 API 返回类型需要窄化 | 使用类型守卫函数或 `instanceof` 检查 |
| .gltf 文件引用外部 .bin 和纹理 | 多文件导入复杂 | 首期仅支持 .glb（自包含），.gltf 后续扩展 |

## Rollback

1. **代码回滚**：所有新增文件独立，修改 Index.ets 仅增加按钮和路由，可安全移除
2. **配置回滚**：若升级 targetSdkVersion 导致问题，还原 build-profile.json5
3. **功能降级**：
   - Phase 0-3 失败 → 回退到 WebView+Three.js 路径（已有完整布展系统）
   - Phase 4 (3DGS) 失败 → 不接入 3DGS，保留占位页，不影响其他功能
   - `Scene.load(stringPath)` 不工作 → 使用 `registerResourcePath` 方案
   - 原生 raycast 不工作 → 用 tap 位置 + 手动计算世界坐标的简化方案
4. **数据安全**：用户导入的模型存储在沙箱，卸载应用自动清除，无外部影响
